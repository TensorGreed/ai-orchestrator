# L2M v0.1.0

The first tagged release of L2M (lsquarem): an open-source, self-hosted orchestrator for putting AI agents into
production safely. Build agents and workflows visually, connect any MCP server, and control every tool call with
approvals, budgets and replay tests. Everything runs on your own servers; L2M does not phone home.

## Install

You need Docker with Compose (linux/amd64 or linux/arm64 images):

```bash
curl -fsSL https://lsquarem.com/install.sh | sh
```

Or, without the script, in an empty folder:

```bash
curl -fsSL https://raw.githubusercontent.com/TensorGreed/l2m/v0.1.0/docker-compose.quickstart.yml -o docker-compose.yml
docker compose up -d
```

Open http://localhost:8080 and sign in as `admin@l2m.local` with the password printed once
(`docker compose logs api`); change it under Settings → Security. The first start makes the master key for stored secrets and keeps it in the data
volume: back that volume up. Details: https://lsquarem.com/docs/getting-started/install

Images: `ghcr.io/tensorgreed/l2m:v0.1.0` (API), `ghcr.io/tensorgreed/l2m-web:v0.1.0` (studio) and
`ghcr.io/tensorgreed/l2m-ner:v0.1.0` (optional add-on), mirrored on Docker Hub as
`lsquarem/l2m`, `lsquarem/l2m-web` and `lsquarem/l2m-ner`. Helm chart: `ops/helm/l2m`.

## Highlights

**Build**
- A visual studio with about 140 node types: triggers (webhook, schedule, form, chat, MCP), flow control,
  loops with branches, sub-workflows, data and file nodes, and an Error output on every node.
- Agents as hubs: attach a chat model, memory and MCP tools; supervisors delegate to worker agents.
- Describe it: say what a workflow should do and get a checked draft to review.
- Ten starter templates that run with no model, key or server; import workflow exports from other builders.
- Models: OpenAI, Azure OpenAI, Anthropic, Gemini, Ollama and any OpenAI-compatible endpoint.

**MCP**
- Any MCP server as a tool, with discovery, health checks and snapshots of its tools.
- One self-hosted MCP gateway: serve your MCP servers and workflows to any MCP client with per-client tokens,
  allow and deny rules per tool, argument-aware rules and per-tool usage and cost.
- An OpenAI-compatible AI gateway (`/v1`) in front of your models.

**Production controls**
- Human approval before write tools, with editable fields; spend and token budgets per project, workflow, user
  or MCP client.
- CI for agents: record a run, replay it after a prompt or model change, and block the release when the behaviour
  changes.
- RBAC with projects and custom roles, SSO (OIDC, SAML, LDAP), MFA, encrypted secrets with external secret
  providers, a hash-chained audit log, OpenTelemetry traces and Prometheus metrics.
- SQLite or Postgres, a queue with workers, multi-instance high availability, backups and restore drills.

**Editor and tools**
- A VS Code extension that runs workflows as coding agents, and an `l2m` command line for MCP checks in CI.

## Verify

Every image is signed with a keyless release identity and carries CycloneDX SBOMs and build provenance; the GitHub
Release has the SBOMs, the image digests and `SHA256SUMS`. How to check them:
https://lsquarem.com/docs/operations/verify-a-release

## Known limits

- Pre-1.0: minor releases may change behaviour; breaking changes are called out in the changelog.
- The quickstart serves plain HTTP on 127.0.0.1. Before opening it to a network, put HTTPS in front of it.
- One SQLite instance is single-writer; use Postgres for several API replicas.
- Python code nodes need a container runtime (docker or podman) for their sandbox; JavaScript code nodes run in a
  WebAssembly sandbox.
